Introduction

Turning operating signals into earlier insight.

Unexpected equipment failures can create downtime, production loss, quality concerns, and safety risk. This model tests whether operational indicators can help identify equipment records that show elevated failure risk within the next 14 days.

The demonstration deliberately uses synthetic data. That allows me to show the machine-learning process publicly while protecting confidential manufacturing information.

Business Question

Which records show elevated risk?

Can recent downtime, cycle-time variation, alarms, maintenance activity, days since preventive maintenance, OEE, and JPH attainment help identify elevated near-term failure risk?

Model Choice

Recall over accuracy alone

Random Forest produced the highest accuracy, but Logistic Regression caught more of the true positive-risk cases. For a maintenance-screening use case, that tradeoff can be more important than headline accuracy.

How I Built It

  1. Created a reproducible synthetic dataset representing common manufacturing indicators.
  2. Defined a binary target representing elevated failure risk within 14 days.
  3. Removed identifiers from the model inputs and used a stratified 75/25 train-test split.
  4. Compared Logistic Regression, Decision Tree, and Random Forest classifiers.
  5. Used class weighting because the positive-risk class is less common.
  6. Evaluated accuracy, precision, recall, F1 score, ROC-AUC, and confusion matrices.
  7. Selected Logistic Regression based on the business need to reduce missed elevated-risk cases.

Features

Downtime hours, average cycle time, cycle-time variation, alarm count, maintenance events, days since preventive maintenance, OEE, and JPH attainment.

Tools

Python, Pandas, NumPy, scikit-learn, Logistic Regression, Decision Tree, Random Forest, Git, and GitHub.

Challenge

The positive-risk class is intentionally less common, which makes accuracy an incomplete metric. A model can look accurate while still missing too many true risks.

What I Learned

Model selection should follow the business consequence of errors. In this case, recall matters because false negatives represent elevated-risk cases the model failed to flag.

Current Result

The working training script generates the dataset, trains all three models, writes evaluation results, and reproduces the reported metrics with a fixed random seed.

Next Validation Step

For production use, I would replace synthetic data with approved plant data, use time-aware validation, check for leakage, tune alert thresholds, assess calibration, and monitor drift after deployment.

Responsible Use

This is a portfolio demonstration, not a production maintenance decision system. Predictions should not replace lockout/tagout requirements, approved reaction plans, inspections, maintenance expertise, or safety escalation. Any real deployment would require verified plant data, subject-matter expert review, controlled access, performance monitoring, and clear response procedures.

Effectiveness Metrics for a Real Deployment

Model recall and precision; false-alarm rate; lead time before failure; unplanned downtime hours; repeat-failure rate; preventive-to-reactive maintenance ratio; avoided downtime; user adoption; and whether alerts result in validated maintenance findings.
